- 条件をそろえるうえでの注意：
  - `lora_alpha` は 32 に固定した。LoRA の更新は alpha/r 倍されるので、r を変えると倍率も変わる（r=4 で 8、r=64 で 0.5）。r を変えても更新の大きさがおおむね揃う、LoRA の標準的な扱いだが、高ランクでは学習がやや遅くなりうる（rsLoRA の指摘）。
  - `warmup_steps` は 6 ステップで固定なので、エポック数を変えると、warmup が全体に占める割合も変わる（10 エポックで 30%、20 で 15%、40 で 7.5%）。cosine で学習率が下がる速さも変わる。
  - 低い学習率を 2e-5 ではなく 5e-5 にした理由：
    - 2e-5 で 40 ステップ回しても、学習率の合計は baseline の最初の約 5 ステップ分しかない。
    - ノートブックの説明では、最初に記録される loss（10 ステップの平均）がまだ 1.5 前後である。つまりその段階では loss はほとんど下がっておらず、2e-5 では何も起きずに終わると予想できる。
    - 5e-5 なら、学習が途中まで進んだ状態を観察できると考えた。
- 比べるときの注意：
  - test は 21 問（根拠あり 15・根拠なし 6）なので、1 問で 4.8 ポイント動く。
  - GPU 上の学習は、seed を固定しても完全には再現しない。そのため、1〜2 問の差はノイズかもしれない。
  - ノイズの大きさは、`seed0` と講師の参考結果（同じ設定・同じ seed）を使って見積もる。
  - 正答率には二項分布の信頼区間を添え、5b の margin（連続値）も合わせて比べる。
- 仮説（2026-11-02、実行前に記録）：
  1. `lora_r`：形式を学ぶには r=4 で足りる。format・content は baseline とほぼ同じになる。学習するパラメータは全体のごく一部なので、学習時間とピークメモリの差も小さい。
  2. `lr5e-5`：形式（`needs_review` を含む JSON）は身につくが、根拠なしの判断は baseline より弱くなる（根拠なしの margin が負に寄る）。最終 loss は baseline より高い。
  3. `lr1e-3`：loss は早く下がる。一方で、FAQ にない質問に近い FAQ 項目を当てはめて断定する失敗が増えるか、出力が崩れる。
  4. `num_train_epochs10`：形式は身につき、content は baseline と同じか少し低い。学習時間は約半分になる。
  5. `num_train_epochs40`：最終 loss は下がるが、test の content は上がらない。学習データへの当てはまりが進むだけだから。
  6. どの設定でも、失敗は「根拠なしの質問に、近い FAQ 項目を当てはめて断定する」型に集中する。
     - 講師の参考結果でも、学習後の失敗 2 件はこの型だった。
     - 「成績はいつ出ますか」には、締切の項目を当てはめていた。
