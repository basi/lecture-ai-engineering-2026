# 第2回 宿題の実験手順（Google Colab）

宿題（基礎・実装・発展）の実験を、Google Colab の T4 GPU で実行する手順です。実験の設計・仮説・結果は [answer.md](answer.md) に書きます。

## 使うファイル

| もの | 場所 | 説明 |
|---|---|---|
| 実行するノートブック | `notebooks/lora_format_tuning_ipynb_v1_<実験名>.ipynb` | v1（`notebooks/lora_format_tuning.ipynb` を Colab で .py に書き出したもの）からの派生。同じ内容の `.py` もある |
| 発展の学習データ | `notebooks/glossary_sft.jsonl` | `scripts/make_sft_dataset.py` の出力（58 語 × 2 テンプレート = 116 行） |
| 結果の置き場所 | `lectures/02/results/<実験名>/` | Colab から持ち帰った JSON を、実験ごとに置く |

派生のノートブックと `glossary_sft.jsonl` は、リポジトリに含めません（手元の `notebooks/` にだけあります）。

## 上書きを防ぐために

- **実験どうしでは上書きされません。** 保存先は実験ごとに分けてあります（Colab では `/content/qlora_lab/<実験名>/`、Drive でも同じ）。
- **上書きが起きるのは、同じノートブックをもう一度実行したときです。** 前の結果を残したいときは、セクション 1 の `EXPERIMENT = "baseline"` を `"baseline_run2"` のように変えてから実行します。
- **ランタイムを削除すると、`/content` の中身は消えます。** 結果を保存してから削除します。
- **ダウンロードしたファイルは、どの実験でも同じ名前になります**（`result.json` など）。手元で混ざらないよう、下の「結果の保存」の方法 A（Drive）か方法 B（zip）を使います。

## 実行の順番

最初に基準を作り、3 つのレベルを早めに揃えます。そのあと、同じパラメータの 2 水準（下げた場合と上げた場合）を続けて流すと、比べやすくなります。無料枠が途中で尽きても、4 番までで 3 レベルとも提出できます。

| 順 | ノートブック（`lora_format_tuning_ipynb_v1_` の後） | 目的 | T4 の目安 |
|---:|---|---|---:|
| 1 | `baseline` | すべての比較の基準。演習欄にも使う。共通の計測コードが動くかの確認も兼ねる | 約 12 分 |
| 2 | `lr5e-5` | 基礎の最初の比較（学習が足りない場合）。ここまでで基礎は提出できる | 約 12 分 |
| 3 | `impl_library_faq` | 実装（架空の市立図書館 FAQ） | 約 12 分 |
| 4 | `adv_glossary` | 発展（用語集で SFT）。`glossary_sft.jsonl` のアップロードが必要 | 約 25 分 |
| 5 | `lr1e-3` | lr の 2 水準を揃える（更新が強すぎる場合） | 約 12 分 |
| 6 | `num_train_epochs10` | エポック数の 2 水準（学習量が半分） | 約 9 分 |
| 7 | `num_train_epochs40` | エポック数の 2 水準（学習量が 2 倍） | 約 16 分 |
| 8 | `lora_r4` | ランクの 2 水準（パラメータが約 1/4） | 約 12 分 |
| 9 | `lora_r64` | ランクの 2 水準（パラメータが約 4 倍） | 約 12 分 |
| 10 | `seed0`（任意） | 設定を変えないときの揺れの目安。ランクの小さな差がノイズかどうかの判断に使う | 約 12 分 |

- 合計は約 2 時間 20 分です。目安は、ライブラリの導入とモデルのダウンロード（1 回あたり 2〜3 分）を含みます。
- GPU の利用上限に達したら、日を分けて続きから実行します。
- **baseline で「5b を飛ばしました: …」と表示されたら、残りを実行する前に知らせてください。** 5b（回答部分だけの評価）のコードは全ノートブックで共通なので、まとめて直します。

## 各ノートブックの手順

1 つの実験につき、1 つのランタイムを使います。

1. Colab で「ファイル → ノートブックをアップロード」を開き、`notebooks/lora_format_tuning_ipynb_v1_<実験名>.ipynb` を選ぶ。
2. 「ランタイム → ランタイムのタイプを変更」で T4 GPU になっているか確かめる（ノートブックの設定で指定済み）。**変更が必要なら、ファイルをアップロードする前に済ませる。** 後から変えると VM が替わり、アップロードしたファイルが消える。
3. 結果の保存方法を決める（下の「結果の保存」を参照）。方法 A なら、セクション 1 のセルにある `USE_DRIVE = False` を `True` に変える。
4. 発展（`adv_glossary`）のときだけ、ここで `glossary_sft.jsonl` をアップロードする（下の「発展：glossary_sft.jsonl のアップロード」を参照）。
5. 「ランタイム → すべてのセルを実行」（Ctrl+F9）。方法 A では、Google ドライブへのアクセスの許可を求められるので許可する。
6. 終わったら、次の 4 つを確かめる。
   - セクション 0 に `Tesla T4` と、ライブラリの版（`transformers: 5.18.0` など）が表示されている
   - セクション 4 に `学習時間: … 秒 | ステップ数: …` が表示されている。ステップ数は、`num_train_epochs10` が 20、`num_train_epochs40` が 80、`adv_glossary` が 150、ほかは 40
   - セクション 5b の表が表示されている（「5b を飛ばしました」は出ていない）
   - セクション 7 に結果の JSON が表示されている（方法 A なら「Drive に保存しました」も）
7. 結果を保存する（方法 B ならダウンロード。方法 A なら Drive に保存済み）。
8. 「ランタイム → ランタイムを接続解除して削除」を実行してから、次のノートブックに進む。

## 発展：glossary_sft.jsonl のアップロード

1. 発展のノートブック（`lora_format_tuning_ipynb_v1_adv_glossary.ipynb`）を開き、T4 であることを確かめて、ランタイムに接続する（「各ノートブックの手順」の 1〜2）。
2. 左端のフォルダのアイコン（ファイル）を開き、上部の「セッション ストレージにアップロード」から、手元の `notebooks/glossary_sft.jsonl` を選ぶ。
3. 一覧のいちばん上の階層（`/content` の直下。`sample_data` と同じ階層）に、`glossary_sft.jsonl` という名前で置かれたことを確かめる。`glossary_sft (1).jsonl` のように名前が変わっていたら、右クリックして名前を変える。
4. ファイルが無いときや 116 行でないときは、モデルを読み込む前（セクション 2）に、アップロードの手順を表示して止まる。
5. ランタイムを削除すると、このファイルも消える。発展をもう一度実行するときは、アップロードし直す。

## 結果の保存

### 方法 A：Google ドライブに保存する（推奨）

- セクション 1 で `USE_DRIVE = True` にして実行すると、結果が自動で `マイドライブ/aie2026/qlora_lab/<実験名>/` に保存される。
  - 保存されるもの：`result.json`・`eval_before.json`・`eval_after.json` と、学習した adapter。
  - 基礎と実装は `test.jsonl` と `gold.json` も、発展は `glossary_test.json` も保存される。
- すべての実験が終わったら、Drive の `aie2026/qlora_lab` フォルダを右クリックして、まとめてダウンロードする。
- adapter を含むので全体で数百 MB になる。不要なら `adapter` フォルダは除いてよい。

### 方法 B：実験名の付いた zip でダウンロードする

- セクション 7 の後にセルを 1 つ足して実行する。
  ```
  !cd /content/qlora_lab && zip -qr /content/{EXPERIMENT}.zip {EXPERIMENT} -x "*/ckpt/*" "*/adapter/*"
  ```
- 左のファイル一覧で `/content/<実験名>.zip` を右クリックして、ダウンロードする。中身は JSON だけで、実験ごとに名前が違うので混ざらない。

## 結果の受け渡し

1. 実験ごとに `lectures/02/results/<実験名>/` を作り、JSON を置く。
   - 方法 A なら、Drive からダウンロードしたフォルダを展開して置く。
   - 方法 B なら、zip を展開して置く。
   - 置き方の例：`lectures/02/results/baseline/result.json`。
2. 置いたら知らせる。JSON から数値を転記して、answer.md の演習欄、各表、仮説との照合、考察を埋める。
3. 結果の JSON をリポジトリに含めるかどうかは、そのときに決める。

## .py を %run で実行する場合

ノートブックの代わりに `.py`（`notebooks/lora_format_tuning_ipynb_v1_<実験名>.py`）を使うこともできます。この方法では、ライブラリの導入を VM ごとに 1 回で済ませられます。

1. 新しいノートブックで T4 を選び、セルで次を 1 回だけ実行する。
   ```
   %pip uninstall -y -q torchao
   %pip install -q "transformers==5.18.0" "peft==0.21.1" "trl==1.14.2" "accelerate==1.15.0" "datasets==5.1.0"
   ```
2. 「ランタイム → セッションを再起動」してから、`.py` を `/content` にアップロードし、`%run lora_format_tuning_ipynb_v1_<実験名>.py` を実行する。
3. 実験ごとにセッションを再起動する（学習後のモデルがメモリに残るため）。保存先は実験ごとに分かれているので、同じ VM で続けて実行しても上書きされない。

## うまくいかないとき

| 症状 | 対処 |
|---|---|
| 「GPU が見つかりません」 | 「ランタイム → ランタイムのタイプを変更 → T4 GPU」。混雑で割り当てられないときは、時間をおいて試す |
| GPU の利用上限に達した | 日を分けて、続きの順番から実行する |
| 「5b を飛ばしました: …」 | 結果の JSON は保存されている（`answer_scores.error` に理由が入る）。baseline で出たら、残りを実行する前に知らせる |
| 発展で `FileNotFoundError: /content/glossary_sft.jsonl` | 上の「発展：glossary_sft.jsonl のアップロード」をやり直す |
| 学習が途中で止まった | ノートブックのセクション 4b の手順で再開する。チェックポイントは `/content/qlora_lab/<実験名>/ckpt/` にある |
| pip の赤い `ERROR: pip's dependency resolver ...` | `cudf` や `pyarrow` に関する警告で、この実験には影響しないので、そのまま進める |
