<details><summary>この文書で使う用語</summary>

**エージェントの動き**

- **ツール呼び出し（tool call）**：モデルが「このツールを、この引数で呼んでほしい」と返すこと。ツールを実行するのはプログラムの側で、その結果（tool return）をモデルに戻す。モデルは結果を読んで、次の呼び出しか回答を返す。
- **requests**：1 つの質問で LLM を呼んだ回数（`--trace` の `[usage]` の `requests`）。ツールを呼ぶと、その結果を読ませるためにもう一度 LLM を呼ぶので、検索を 1 回して答えると 2 になる。
- **tool_calls**：1 つの質問で実行したツールの数（`[usage]` の `tool_calls`）。承認で拒否した呼び出しは、実行していないので数えない。
- **並列の呼び出し**：1 回の応答の中で、複数のツールをまとめて呼ぶこと。LoRA と QLoRA の検索を 1 回の応答で両方呼べば、tool_calls が 2 でも requests は 2 で済む。1 つずつ順に呼ぶと、requests は 3 になる。
- **INSTRUCTIONS**：エージェント全体への指示（`app/agent.py` の 31〜38 行目）。LLM を呼ぶたびに、指示としてモデルに渡る。
- **ツールの説明文（docstring）**：ツールにした関数の docstring。型ヒントと一緒に、そのままモデルへのツールの説明になる。モデルはこれを読んで、使うかどうかと、どんな引数で呼ぶかを決める。

**実験の条件**

- **変種**：基準（V0 `baseline`）の INSTRUCTIONS か、ツールの説明文を、1 か所だけ変えた条件。V0〜V7 と呼ぶ。
- **試行**：同じ条件（変種 × 質問）を、何回目に実行したか。t1〜t3。
- **エンジン**：質問に答える側。`pydantic`（演習のエージェント）、`ask`（第1回の素の LLM）、`adk`（ADK 版）、`pi`（Pi）の 4 つ。
- **自動チェック**：回答とツール呼び出しを、決めておいた規則で機械的に判定したもの（例：「基礎・実装・発展を全部含む」）。規則は `lectures/03/conditions.toml` に書いた。最後の判断は、回答を読んで行う。
- **承認待ち（`DeferredToolRequests`）**：`requires_approval=True` のツールをモデルが呼んだときに、実行せずに返ってくる呼び出しの一覧。

</details>

## 実装

### 作ったもの

- `save_learning_log(title: str, content: str)`（`app/tools.py`）：学習の記録を、`learning_log/` に Markdown のファイルとして保存する。
  - ファイル名は「日時-題名.md」（例：`20261103-153000-LoRAとQLoRA.md`）。題名のうち、ファイル名に使えない文字（`/`・`\`・`..`・制御文字など）は `-` に置き換える。
  - 保存先が `learning_log/` の中に収まることを確かめる。`open(..., "x")` で開くので、上書きしない（同じ名前があれば `-2`、`-3` を付ける）。
  - docstring：「学習の記録を learning_log/ フォルダに Markdown ファイルとして保存する。利用者に学習の記録や保存を頼まれたときだけ使うこと。title は記録の題名、content は本文（Markdown）。保存は取り消しにくいので、このツールを呼ぶと、保存の前にプログラムが利用者に承認を求める（会話の中で先に確認を取らなくてよい）。承認されなかったときは保存しない。」
  - `learning_log/` は `.gitignore` に入っているので、保存した記録は共有されない。
- 登録（`app/agent.py`）：`agent.tool_plain(tools.save_learning_log, requires_approval=True)`。エージェントの `output_type` に `DeferredToolRequests` を加えた（`output_type=[str, DeferredToolRequests]`）。
- 承認の CLI（`run_with_approval` と `ask_approval`）
  - モデルが `save_learning_log` を呼ぶと、実行はそこで止まり、`result.output` に承認待ちの一覧（`DeferredToolRequests`）が返る。
  - 承認待ちの呼び出しごとに、ツール名と引数を見せて「保存してよいですか？ [y/N]」と聞く。y か yes だけを承認とし、それ以外の答えと、入力が無いとき（EOF）は拒否する。
  - 承認は `True`、拒否は `ToolDenied("利用者が保存を断りました。保存せずに答えてください。")` として `DeferredToolResults` にまとめる。それを、それまでの会話（`message_history=result.all_messages()`）と一緒に渡し、もう一度 `run_sync` を実行する。承認待ちが続く間は、これを繰り返す（最大 5 回）。
  - `usage=result.usage` も渡すので、`--trace` の `[usage]` は、2 回の実行の合計になる。
- 比較用スクリプトからは、承認か拒否かをシナリオどおりに自動で答える。保存先は、試行ごとの一時フォルダに差し替え、保存された中身を JSON に記録する（`learning_log/` には書かない）。

### 気づき

- **Pi のプロンプトは「何ができるか」を書き、自分の INSTRUCTIONS は「いつ、何をするか」を書いている。** Pi は、ツールの一覧と使い方の注意（read を使う、簡潔に、パスを示す）だけで、いつ探すか、見つからないときどうするかを決めていない。自分のは、答える前に必ず検索する、見つからなければ推測しない、最後に回を示す、と手順と制約を決めている。
- **規則が無いと、探すかどうかを質問の語で決める。**
  - Pi は、講座名（AIE2026）の入った q01 だけファイルを探し、3 回とも用語集の定義にたどり着いて正しく答えた。
  - q02（LoRAとQLoRA）と q04（RLHF）は、一般の知識で答えられる質問と判断したとみられ、1 回も探さなかった。用語集にある LoRA・QLoRA の定義（第2回）も使わなかった。
- **汎用のエージェントは、探す分だけ高くつく。**
  - q01 で、Pi は LLM を 4〜8 回呼び、入力は 7,228〜19,438 トークンだった（V0 は 2 回・959）。
  - 専用のツール（`search_glossary`）は、探す手間をツールの中に閉じ込めて、1 回の呼び出しで定義を返す。Pi は find・grep・read を組み合わせて同じことをするので、ファイルの中身を何度も読む。
  - grep の「レベル」は、定義の行に当たらない（定義は「3段階」と書いてあり、「レベル」の語が無い）。そのため、探し方によって、ツールの回数が 3〜7 回と揺れた。
- **プロンプトの長さの 7 割は、Pi 自身の説明だった。** 1,878 字のうち 1,329 字（71%）は、Pi のドキュメントの場所の案内で、質問に答えるのには使われない。固定分は呼び出しのたびにかかり、1 回目の入力は Pi が約 1,270 トークン、V0 が 413 だった。
- **強い制限は、どちらもプロンプトの外に置いている。** Pi のプロンプトには、ファイルを消さない、確認を取る、といった規則が無い。今回の安全は、ツールを読み取り専用の 4 つに絞り、data/ だけを複製した一時フォルダで動かす、という外側の設定で作った。自分のエージェントも、保存の承認はコード（`requires_approval=True`）で止めている。
- **講座向けに使うなら、AGENTS.md に書く。** Pi のプロンプトは、利用者の指示を AGENTS.md などのファイルから読み込む作りになっている。自分の INSTRUCTIONS にある「用語集を確かめる」「推測しない」「回を示す」を AGENTS.md に書けば、Pi でも近い振る舞いになると考えられる（今回は確かめていない）。

1. 「q01 は grep と read で data/glossary.json を探して正しく答える」「LLM の呼び出しは 3〜8 回」「第N回は付けない」は、3 つとも当たった（正しい回答は 3/3、turn は 4〜8、第N回は 0/3）。
