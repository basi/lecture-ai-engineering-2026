# 第1回 解答

## 演習

- 講座に固有の質問（宿題の3レベル）へのモデルの回答（要約でよい）：`gemini-3.5-flash-lite` は3回とも、講座固有の定義は分からないまま「一般的な初級・中級・上級の課題」と推測して説明した。`gemini-3.5-flash` も成功した2回は、同様に難易度別の課題として説明した。具体例や説明の長さは実行ごとに異なった。
- 用語集の正しい意味と比べて気づいたこと：正しくは、基礎（講義内容の確認）・実装（自分でコードを書く）・発展（調査や試行）の3段階で、どれか1つに取り組めば宿題は完了する。モデルの説明は一般論としては自然だが、講座独自の定義や「どれか1つで完了」という条件を答えられず、もっともらしい推測になっていた。
- 表示できたトークン数（入力 / 出力）：`gemini-3.5-flash-lite` は3回とも入力21、出力657 / 473 / 475。`gemini-3.5-flash` は成功した2回で入力21、出力702 / 742。もう1回は503エラーでトークン数なし。

## 宿題

### 基礎

- やったこと：同じ質問「AIE2026の講座の宿題にある『3レベル』とは何ですか？」を `gemini-3.5-flash-lite` と `gemini-3.5-flash` で各3回実行した。
- 結果：`gemini-3.5-flash-lite` は3回とも回答し、出力の長さは657、473、475トークンだった。`gemini-3.5-flash` は2回回答（702、742トークン）、1回は503エラーだった。回答はいずれも一般的な難易度別課題の説明で、講座固有の定義とは異なっていた。
- 気づき・疑問：同じ質問・同じモデルでも回答の長さや説明の細部は変わった。知らない講座固有の情報を一般論で補ってしまうため、用語集などの信頼できる情報との照合が必要。また、モデルの混雑で503エラーになることも確認した。

### 実装

- やったこと：`app/ask.py` を改修し、初回の質問と回答を会話履歴に追加して、次の質問にも同じ履歴を渡すようにした。コマンドラインで質問を指定した場合も、その質問のあとに対話を続けられる。空入力は読み飛ばし、「終了」「exit」「quit」または入力終了で終了する。
- 結果：履歴を使った2回の質問で、2回目のリクエストに「最初の質問・最初の回答・続けて質問」が含まれることをテストで確認した。空入力を読み飛ばして次の質問を受け付けるテストも追加した。`uv run pytest` は13件すべて成功した。
- 気づき・疑問：質問だけでなくモデルの回答も履歴に追加することで、続けて質問したときに前のやり取りを踏まえた応答ができる。今回はAPIを直接呼ばないテストで履歴の受け渡しを確認したため、実際のモデルでの回答内容は別途試して確認したい。
