## 演習

- 用語集の正しい意味と比べて気づいたこと：正しくは、基礎（講義内容の確認）・実装（自分でコードを書く）・発展（調査や試行）の3段階で、どれか1つに取り組めば宿題は完了する。モデルの説明は一般論としては自然だが、講座独自の定義や「どれか1つで完了」という条件を答えられず、もっともらしい推測になっていた。
- 表示できたトークン数（入力 / 出力）：`gemini-3.5-flash-lite` は3回とも入力21、出力657 / 473 / 475。`gemini-3.5-flash` は成功した2回で入力21、出力702 / 742。もう1回は503エラーでトークン数なし。

## 宿題

### 基礎

- やったこと：同じ質問「AIE2026の講座の宿題にある『3レベル』とは何ですか？」を `gemini-3.5-flash-lite` と `gemini-3.5-flash` で各3回実行した。
- 結果：

  | モデル | 試行 | 成功 | 入力トークン（成功時） | 出力トークン（成功時） | 応答時間 |
  |---|---:|---:|---:|---|---|
  | `gemini-3.5-flash-lite` | 3 | 3 | 21 | 657 / 473 / 475 | 未記録 |
  | `gemini-3.5-flash` | 3 | 2 | 21 | 702 / 742 | 未記録 |

  `gemini-3.5-flash` の失敗1回は503エラーで、トークン数はありません。成功した回答はいずれも一般的な難易度別課題の説明で、講座固有の定義とは異なっていました。
- 気づき・疑問：同じ質問・同じモデルでも回答の長さや説明の細部は変わった。知らない講座固有の情報を一般論で補ってしまうため、用語集などの信頼できる情報との照合が必要。また、モデルの混雑で503エラーになることも確認した。

### 実装

- やったこと：`app/ask.py` を改修し、初回の質問と回答を会話履歴に追加して、次の質問にも同じ履歴を渡すようにした。コマンドラインで質問を指定した場合も、その質問のあとに対話を続けられる。空入力は読み飛ばし、「終了」「exit」「quit」または入力終了で終了する。
- 結果：履歴を使った2回の質問で、2回目のリクエストに「最初の質問・最初の回答・続けて質問」が含まれることをテストで確認した。空入力を読み飛ばして次の質問を受け付けるテストも追加した。実装時の `uv run pytest` は13件すべて成功した。
- 気づき・疑問：質問だけでなくモデルの回答も履歴に追加することで、続けて質問したときに前のやり取りを踏まえた応答ができる。今回はAPIを直接呼ばないテストで履歴の受け渡しを確認したため、実際のモデルでの回答内容は別途試して確認したい。

### 発展

- やったこと：各応答のAPI呼び出し時間と、レスポンスに含まれる入力・出力トークン数を表示するようにした。`--once` を追加し、質問・`AIE_MODEL` を変えた単発実行を比較しやすくした。
- 結果：

  | 確認項目 | 実行結果 |
  |---|---|
  | 全テスト | `uv run pytest` — 16件成功 |
  | 成功応答の計測表示 | テストで応答時間125 ms、入力12・出力7トークン、status `ok` を確認（固定したテスト値。実APIの計測ではない） |
  | APIエラー時の計測表示 | テストで429、応答時間250 ms、トークン数 `n/a` の表示と例外の再送出を確認（固定したテスト値） |
  | 過去の実API比較 | 基礎欄のとおり。応答時間は未記録 |
  | 今回の実API比較 | 未実施。モデル・質問別の応答時間とトークン数は未計測 |

  クライアントは対話中に再利用し、`--once` 終了・通常終了・APIエラー時に閉じる。単独で `ask()` を呼ぶ場合も、作成したクライアントを閉じる。
- 気づき・疑問：会話を続けると履歴も毎回送信され、入力トークン数が変わるため、比較条件を揃えるには `--once` で1回ずつ実行する。短時間に何度も呼び出すと無料枠のレート制限（429）に達することがある。比較ではモデル、質問、実行時刻、成功・失敗、応答時間、トークン数を記録し、モデルごとの利用上限と合わせて考察する必要がある。
